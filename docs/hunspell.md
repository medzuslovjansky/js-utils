# Hunspell dictionaries

Hunspell dictionaries (`.dic`/`.aff`) are generated by `slovosbor`, which maintains the live lexicon.

This document describes Hunspell format constraints measured against `hunspell 1.7.3`.

## Generator Workflow

For each lemma streamed from the lexicon:

1. `normalize({ isv, addition, partOfSpeech })` — handles variants and biaspectual verbs.
2. `inflectLemma()` — expands paradigm cells to CoNLL-U tokens.
3. `transliterate(form, code)` — produces target orthographies.
4. Output `.dic` lines with flags representing morphological cells.

Dictionaries should be generated in a batch build rather than dynamically per request.

## Targets

Files are named by standard BCP 47 subtags:

| File | Flavorisation |
|---|---|
| `isv-Latn` | `FlavorisationBCP47.Latin` |
| `isv-Cyrl` | `FlavorisationBCP47.Cyrillic` |
| `isv-Latn-x-etymolog` | `FlavorisationBCP47.LatinEtymological` |

Transliterate complete inflected forms before mining affix rules: transliteration does not commute across stem-ending boundaries (e.g. `bol+ja` → `боља` vs `болја`; `pol+je` → `ⱂⱁⰾⱐⰵ` vs `ⱂⱁⰾⰹⰵ`).

## `.aff` Configuration

Static configuration per target script:

```
isv-Latn             TRY aoienrtmljusvkpdzěhbgyčšžcf
                     WORDCHARS abcčdeěfghijklmnoprsštuvyzž-
isv-Cyrl             TRY аоиенртмуслвјкпдзєхбгычшжцљфњ
                     WORDCHARS абвгдеєжзијклљмнњопрстуфхцчшы-
isv-Latn-x-etymolog  TRY aoienrtmjlsvkpdzuųěhbgyčšåcžęȯfŕńć́ĺėđśź
                     WORDCHARS ́aåbcčćdđeěėęfghijklĺmnńoȯprŕsśštuųvyzźž-
```

`BREAK -` enables hyphenated compound validation when components are valid words.

## Morphological Flags

Each flag represents a morphological cell (e.g. `Nom|Sing`). Affix rules use zero-length strip/add rules to attach morphological fields:

```
# .aff
SFX 1001 Y 1
SFX 1001 0 0 . po:noun is:Nom|Sing

# .dic
domom/1005 st:dom
```

`hunspell -m` reports the lemma, part of speech, and feature bundle. Flag IDs should deterministically encode part of speech and feature slots (e.g. block prefix + index) to stay stable across rebuilds. Hunspell numeric flags are capped at 65535.

This emits flat `.dic` files without affix compression; each inflected form occupies its own line with an identity affix rule.

## Hunspell Format Behavior

- **Duplicate words:** Accepted across multiple lines.
- **Flagless duplicates:** Duplicate words without flags collapse to the first occurrence. With flags, both survive (including distinct `st:` homographs).
- **`st:` scoping:** Cannot be placed on shared flags; must appear per line in `.dic`.
- **Bare analyses:** Every dictionary word yields an additional bare entry without morphological fields in `-m` output.
- **Morphological inheritance:** Fields on lemma lines leak into all derived analyses. Keep invariant fields on the line and inflected features on affix rules.
- **Word count header:** Overcounting line 1 by >5x triggers `Hash Manager Error : 3` and rejects all entries. Use an exact form count.

## Lexicon Edge Cases

- **Bound morphemes:** Lemmas beginning or ending with a hyphen (`-lěťje`, `-kråtno`) should be excluded to prevent invalid compound matches under `BREAK -`.
- **Multi-word entries:** Skipped by `inflectLemma()`. Multi-word parsing requires explicit `head`/`deprel`/`Uninflect` tags in source data.

## Morphological Analysis

For server-side morphological analysis, query the precomputed `(form → lemma, feats)` lookup table generated during lexicon dump rather than executing `hunspell -m`.
